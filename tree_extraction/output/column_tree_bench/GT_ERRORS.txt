GT_ERRORS — columns the GT uses where a model was scored "wrong" but the error
is in the answer key, not in the model.
Reviewed 2026-10-02 from the column-tagging benchmark (output/column_tree_bench).

The answer key has two layers, and an error can sit in either:
  - GT xlsx: what the volunteers recorded (data/un_processed_papers/<paper>/<paper>.xlsx)
  - derived key: how column_role_bench.derive_labels turns the GT into one tag per
    column (by matching cell values, plus the rule "rank/authority columns are identity")

Note on 1, 2 and 4: template_descriptions/measurementType.md currently says the
opposite of the verdicts below (quoted under each). If the verdicts stand, that
file should change too, or the tree and the mapper will keep following it.

Template today (measurementType.md): '"Overwintering stage" / "Overw. stage" /
         "Diapause stage" = egg/larva/pupa/adult -> measurementType (the stage the
         species overwinters in), NOT lifeStage'

3. Attiwilli2022 — 'Body mass' (Table 2)       error in: derived key (+ parsing)
===============================================================================
Table:   Attiwilli2022_full.md#1 — paper Table 2, "Results from linear models
         with logged body mass, logged wing length and logged proboscis length as
         the response variables and family and habitat as predictors"
Source:  first header cell is EMPTY; 'Body mass' is a section row spanning the
         table (<td colspan="4">Body mass</td>), followed later by 'Wing length'
         and 'Proboscis length' sections:
           (blank)                        | Estimate mean ± SE | t-statistic | p
           Body mass (section row)
           Intercept (Hesperiidae–Ecotone)| 4.45 ± 0.146       | 30.56       | <0.0001
           Lycaenidae                     | -0.98 ± 0.169      | -5.80       | ...
Parsed:  Body mass | Estimate mean ± SE | t-statistic | p   (the section label
         became the first column's header)
Values:  Intercept (Hesperiidae–Ecotone); Lycaenidae; Nymphalidae; Papilionidae;
         Pieridae; Habitat Forest; Habitat Open
GT xlsx: does not use this table (its 'Body mass' rows come from #6, e.g.
         '174.2 ± 139.13', '12.4 - 378.5')
Key:     verbatimIdentification (57% of cells are GT names: the families)
Models:  gemma, tev1, nimble = measurementType; nimble_full and all trees =
         verbatimIdentification
Verdict: the column does not hold body-mass values; it is the predictor list of
         a regression table, and 'Body mass' is a section title. Correct key:
         none (statistics table). Two fixes: the key must not label a column
         from a section title, and the parser must treat a full-width
         'Body mass' row as a section (a header-tree case; the production code
         may already handle it).
