Marked-column categories

v20 tried to read columns marked with one sign (an X) and blank elsewhere as categories of one property: trait = a name for the group, value = the marked column's name. This page shows each group on the tuning papers, the name gemma proposed, what nimble decided, and, from a what-if run that applied every group regardless, whether the scorer counted our name as the same as a GT trait.

How it went

Nimble read none of the 10 groups as categories, so v20 changed no row and every score stayed at v18's. For sampling sites (Heiva2013), plots by elevation (Fontanilla2019) and the other non-trait tables that was right. It also turned down Odanaka2019's management-intensity columns (0.99 "separate"), the one group the GT scores as a trait. In the what-if, the scorer matched gemma's name "Habitat/Condition" to the GT's "Management intensity" and Odanaka2019 rose from 0.786 to 0.912. No other paper's F1 moved, because their extra rows are outside what the GT scores.
